## 1. Get your keys

3. You get two keys:

   - **Site key:** public. It goes in the HTML.

   - **Secret key:** private. Only PHP uses it, and it must never appear in a template.



## 2. Store the keys

Add both keys to [config.php](config.php) next to the database settings.

## 3. Show the CAPTCHA (front end)

For [create_accout.html.twig](templates/create_accout.html.twig) (and [login.html.twig](templates/login.html.twig) if you want it there too):

2. Inside the `<form>`, above the submit button, add a `div` with class **`g-recaptcha`** and a **`data-sitekey`** attribute.

3. Don't hard-code the key in the template. Pass it from [create_accout.php](create_accout.php) through `render()`, the same way you pass `error`. That way the Twig criterion stays clean.



When the user ticks the box, Google adds a hidden field called **`g-recaptcha-response`** to the form automatically.



## 4. Check it on the server (this is what earns the marks)

Showing the box on its own does nothing. In [register_process.php](register_process.php), straight after the POST check and **before** any database work:

1. Read `$_POST['g-recaptcha-response']`. If it's empty, the user didn't tick the box.

2. Send a **POST** request to `https://www.google.com/recaptcha/api/siteverify` with these fields:

   - `secret`: your secret key

   - `response`: the token from step 1

3. In PHP you can send it with `file_get_contents` plus `stream_context_create` (method POST, body built with `http_build_query`), or with cURL.

4. Google replies with JSON. Decode it with `json_decode` and check whether **`success`** is `true`.

5. If it isn't, redirect back with something like `?error=captcha`, the same pattern you already use for `missing` and `mismatch`. Then add a matching message to the template.

[ASSISTANT] Yes. Every hosted CAPTCHA (Google, hCaptcha, Cloudflare Turnstile) needs keys, so the way around it is a CAPTCHA that runs on your own server. Two options:



## Option A: Your own CAPTCHA with sessions (recommended)

It needs no account, no keys and no internet, and you already use sessions. The idea:



1. **Make the challenge.** When the form page loads ([create_accout.php](create_accout.php)), generate the challenge in PHP. Either:

   - a random sum, e.g. "What is 7 + 4?" (`random_int` for the numbers), or

   - a random string of 5–6 characters (shown as an image, see the next point).

2. **Save the answer in `$_SESSION`**, e.g. `$_SESSION['captcha']`. Never put the answer in the HTML or a hidden field, or a bot can just read it.

3. **Show the question** through `render()` and add an input such as `name="captcha"` to the form.

   - For an image instead of text: add a small separate PHP file that draws the string with the **GD** extension (`imagecreatetruecolor`, `imagestring`, add a few random lines for noise, output with `imagepng`). The page links to it with `<img src="captcha.php">`. Check GD is installed with `php -m | grep gd`.

4. **Check it** in [register_process.php](register_process.php), before any database work:

   - Compare `$_POST['captcha']` with `$_SESSION['captcha']`. For the image version, compare without caring about upper and lower case.

   - **Then `unset` the session value**, whether the answer was right or wrong. Otherwise one correct answer could be reused for many sign-ups.

   - If it's wrong, redirect with `?error=captcha`, the same pattern as your other errors.

5. **Test it:** a wrong answer gives the error and creates no account. Reload the page and you should get a new challenge.



session_start() must come first in any file that reads or writes `$_SESSION`. [create_accout.php](create_accout.php) doesn't start a session yet.



## Option B: A Composer library

**`gregwar/captcha`** creates the distorted image for you with no keys: `composer require gregwar/captcha`. You still store its phrase in the session and check it yourself, just like steps 2 and 4 above. It's less work, but you write and learn less of it.



**My pick:** Option A with the image. It clearly counts as "captcha used", shows you understand sessions, and puts your own code in front of the marker. The math version is quicker to build if you're short on time.
