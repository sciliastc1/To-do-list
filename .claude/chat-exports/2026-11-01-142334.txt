
[ASSISTANT] `index.php` never loads `base.html.twig` itself. It only names `index.html.twig`, and Twig finds the rest.



**1. `index.php` names one template.**

```php

render('index.html.twig', [...]);

```

That string is just a filename, not a path.



**2. `render()` turns the name into a file.**

In [twig.php](twig.php), the `FilesystemLoader` was given `__DIR__ . '/templates'`. When Twig is asked for `index.html.twig`, it looks for `templates/index.html.twig`. That folder is the only place the loader searches, which is why every template must live inside it.



**3. `index.html.twig` asks for the base template.**

Its first line is:

```twig

{% extends 'base.html.twig' %}

```

While Twig reads the file, it sees `extends`. It uses the same loader to find `templates/base.html.twig` and loads that too.



**4. Twig merges the two.**

- `base.html.twig` is the outer page: `<head>`, navbar, closing tags. It has an empty slot, `{% block body %}{% endblock %}`.

- `index.html.twig` defines its own `{% block body %}...{% endblock %}`.

- Twig puts that content into the slot in base. The result is one complete HTML page.



`partials/create_task.html.twig` works the same way. The `{% include 'partials/create_task.html.twig' %}` line makes Twig look up `templates/partials/create_task.html.twig`, using the same loader.



The consequences:

- Template names are relative to `templates/`, so `partials/create_task.html.twig` means `templates/partials/create_task.html.twig`.

- If you rename or misspell a file, Twig throws "Unable to find template".

- A child template doesn't need `require` or `include` for the base, because `extends` handles it.



The variables work the same way. `index.php` passes `name`, `tasks` and so on to `render()`. Twig makes them available in the child template and in the base it extends.
